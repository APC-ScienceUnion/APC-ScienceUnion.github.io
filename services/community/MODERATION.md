# 评论审核

命中词库的评论和留言进入独立的 `comment_reviews` 表，公开列表、计数和分页只读取 `comments`。非命中发言直接发布；既有发言不追溯隐藏。所有角色都经过相同筛选。站长在个人中心查看待审核列表及命中线索，选择通过或不通过。通过时事务内创建一条公开评论，重复操作返回冲突；作者可查看自己的待审/未通过内容并撤回。撤回、拒绝、审核人、审核时间及词库版本留在私有数据库和备份中。

## 词库来源与清洗

- 来源：<https://github.com/konsheng/Sensitive-lexicon>，固定提交 `d967c30b053fa40b06c5a0dddf0be493f2dfae46`。原 MIT 许可保留在 `src/moderation-LICENSE.txt`。
- 第一版 142 条：140 条人工选取上游词，2 条本站补充（天安门事件、六四事件）。每条在 `src/moderation-lexicon.json` 记录原文件来源和本站审核分类；分类不表示法律结论。
- 未导入冠以腾讯/网易名称的混合大词表、网址表、单字/数字、短于 3 字的词、普通人名机构名、民族宗教名称和单纯医学化学名词。筛选后的 1239 条候选再次逐项选取，仅保留相对明确的内容线索。
- 不使用上游整库自动更新，不将第三方词库或源码作为可执行代码。部署包包括选定词、原许可及匹配模块，不向浏览器发送词表。
- 运行时仅作 NFKC、大小写、空白和不可见格式字符归一化，原文不改写。未实现谐音、拼音、繁简转换、图片识别、语义判断或所有插入标点的变体检测。

## 维护与限度

修改 JSON 中的条目后运行 `npm test --prefix services/community`，检查正常科普回归语料和权限测试，再打包部署。运行 `node tools/audit_community_lexicon.mjs <上游本地 Git 仓库路径>` 可核对来源、原许可证并报告现有中文文章的命中情况；此审计不修改文章，也不阻止文章发布。词库内容 SHA-256 的前 16 位存于审核记录，用于区分更新版本。缺失或损坏词库将阻止服务启动，不静默放行。误报词应单独移出词表；不要用“消息中只要有白名单词就免审”的规则。

词库只是人工审核辅助，不能覆盖所有有害内容或证明合规；历史讨论、引用和反驳也可能命中。此版本仅扫描新提交的评论正文和留言正文，不审核昵称或历史评论。文章审计出现命中时应人工判断语境，不应盲目删词或修改文章。

部署为加表变更，原评论不变。回退旧程序不会泄漏已待审内容，但旧程序不筛查新发言；生产故障应停止社区服务后修复，不能悄悄回退为无审核写入。备份包含审核表，恢复时需与评论表一同恢复。
